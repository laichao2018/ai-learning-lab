# 模型参数量、精度与资源需求

## 参数量是什么意思

模型名称中的 `0.6B`、`7B`、`32B` 和 `70B` 描述可学习参数的数量。`B` 表示 billion，即十亿：

- `0.6B`：约 6 亿个参数。
- `7B`：约 70 亿个参数。
- `32B`：约 320 亿个参数。
- `70B`：约 700 亿个参数。

以线性层为例：

```text
y = Wx + b
```

矩阵 `W` 和偏置 `b` 中的数值就是参数。Transformer 的 Attention、前馈网络和 Embedding 等模块都包含参数。训练会根据数据调整参数；推理通常只读取它们。

参数不是一条条可直接读取的知识，也不是“一个参数保存一个事实”。知识、语言规律和行为模式分布在大量参数之间。

## 参数更多通常带来什么

在架构、训练数据和训练方法相近时，参数更多通常意味着：

- 更强的模式表达能力。
- 更高的复杂任务能力上限。
- 更好的知识记忆和泛化潜力。
- 在推理、代码和多语言任务上可能表现更好。

但参数量只是一个变量。训练充分、数据更好、架构更新的小模型，可能在特定任务上超过更大的旧模型。

## 参数更多的代价

- 权重文件更大。
- 需要更多内存或显存。
- 每个 token 的计算量通常更高。
- 推理延迟和部署成本通常更高。
- 训练与微调需要更多资源。
- 多卡部署会增加通信和工程复杂度。

模型选择是在质量、速度、成本、硬件和隐私之间取平衡，而不是越大越好。

## 权重大小如何估算

仅计算权重时：

```text
权重大小 ≈ 参数数量 × 每个参数占用的字节数
```

常见格式：

- FP32：4 字节/参数。
- FP16/BF16：2 字节/参数。
- INT8：约 1 字节/参数。
- INT4：约 0.5 字节/参数，另有少量量化元数据。

7B 模型的粗略估算：

```text
FP32：7B × 4 bytes ≈ 28 GB
FP16：7B × 2 bytes ≈ 14 GB
INT8：7B × 1 byte  ≈ 7 GB
INT4：7B × 0.5 byte ≈ 3.5 GB
```

以上是十进制近似值。实际大小还受模型结构、量化分组、元数据和文件格式影响。

## 权重文件不等于运行内存

推理时除了权重，还需要：

- KV Cache：保存 Attention 的中间状态，随上下文长度和并发数增加。
- Activations：网络计算产生的中间结果。
- 临时缓冲区、运行库和框架开销。
- 多模态模型的视觉或音频编码器。

所以 4 GB 的量化权重文件不代表 4 GB 内存一定能运行。Hugging Face Accelerate 可以估算加载模型权重所需空间：

```bash
accelerate estimate-memory Qwen/Qwen3-0.6B --dtypes float32 float16 int8 int4
```

该结果主要是权重加载估算，不等于完整推理的峰值内存。

## 量化是什么

量化使用更低精度表示权重，例如从 FP16 降到 INT8 或 INT4，从而减少存储、内存和计算成本。代价可能是精度损失，并且实际速度取决于硬件和推理实现是否对该格式优化。

量化不会改变“模型有多少个参数”，只改变这些参数以多少 bit 存储和计算。因此 7B FP16 与 7B INT4 参数数量相同，权重体积不同。

## Dense 与 MoE

Dense 模型在每次生成时基本使用全部参数。MoE（Mixture of Experts）拥有多个专家子网络，每个 token 通常只激活其中一部分。

MoE 经常同时标注：

- `total parameters`：总参数量，主要影响权重存储和加载。
- `active parameters`：每个 token 参与主要计算的参数量，更直接影响计算成本。

“总参数 100B、激活参数 10B”不等于 10B Dense 模型：它仍要存放接近 100B 的权重，但每个 token 的主要计算量更接近激活部分。实际开销还取决于路由和并行实现。

## 推理与训练的资源需求

推理主要需要权重、KV Cache、Activations 和缓冲区。训练还需要梯度、优化器状态及更多中间结果，因此资源需求远大于仅加载或推理。

这就是为什么个人电脑可能运行一个量化模型，却无法完整训练同等规模模型。微调比预训练便宜，但仍受精度、batch size、序列长度和微调方法影响。

## 参数量不能单独决定什么

仅看参数量无法确定：

- 上下文长度。
- 知识是否最新。
- 是否会产生幻觉。
- 在某个特定任务上是否更强。
- 实际输出速度和吞吐量。
- 是否允许商业使用。
- 是否支持图片、音频或视频。
- 工具调用是否稳定。

这些还取决于模型架构、训练数据、训练方法、推理框架、硬件、许可证和运行配置。

## 选择模型的顺序

1. 任务和语言是否匹配。
2. Model Card、许可证与限制是否满足需求。
3. 在真实任务上的评测和试用结果。
4. 上下文、结构化输出及工具调用能力。
5. 参数量、精度与本机硬件是否匹配。
6. 延迟、吞吐量和费用。

本课程先使用 `Qwen/Qwen3-0.6B`，目的是低成本走通流程，不代表它具有最佳回答质量。流程跑通后再比较更大模型，才能观察参数规模带来的实际收益和代价。
